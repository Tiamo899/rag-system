# 检索质量调优说明（2026-11-18）

本轮改造的目标不是"加功能"，而是把**答案质量**和**响应速度**同时拉到可答辩的水平。
所有指标都能用仓库里的脚本复现，不依赖人工感觉。

## 1. 问题定位

| 现象 | 度量 | 根因 |
|------|------|------|
| 资料片段太碎 | 144 块 / 20 文档，中位块长 **122 字符** | markdown 策略逐标题切块，政策类文档标题极密（一节一句话），出现大量碎片 |
| top-3 被同一文档包场 | 10 题里 3 题三条来源全来自同一文档 | 相邻小节重复命中，三个引用位只覆盖一处内容 |
| 限定条件丢失 | 上下文仅 707 字 | "补考后仍不及格""三天至一周"这类限定常被切到未召回的邻块 |
| 生成慢 | 平均 13s，个别 80s | 主模型 glm-4.7-flash 免费池拥堵，频繁 429 触发退避 |

## 2. 改造内容

### 2.1 分块：章节内合并 + 收尾合并（`services/chunking/splitter.py`）

- 先按标题切小节，再在**同一一级标题**内把小节合并到 `35% × chunk_size`（500 tokens≈2000 字符 → 约 700 字符）以上；
- 合并上限仍是 `chunk_size`，超长小节回落段落切分；
- 收尾阶段把小于下限一半的孤块**向前**并入，避免"附则一句话"成块；
- 只向前合并、且前一块本身已达标才合并——防止跨章节把甲章尾巴拼到乙章头上（有回归测试）。

结果：**144 块 → 28 块**，中位块长 **约 700 字符**。

### 2.2 检索后处理（`services/search/postprocess.py`）

- `expand_with_neighbors()`：命中块从 ES 取同文档 ±1 邻块，以【上文/下文相邻段落】拼在正文后，单块上限 2600 字符；任何异常 fail-soft 返回原块。
- `diversify()`：同一文档最多占 2 个引用位；三条来源合计受 `CTX_BUDGET_CHARS`（默认 2600）约束，至少保留 2 条。
- `strip_boilerplate()`：剔除示例文档每篇重复的免责声明行，不占上下文预算。
- 主流程（`nodes.py`）与调试台（`trace.py`）共用同一套后处理，保证"调试台看到什么，线上就按什么答"。

### 2.3 引用一致性

`evaluate_node` 把选中的 3 条写入 `state.selected_chunks`，`generate_node` / `graph.py` 的 sources 直接取这批块，避免"上下文是 A 组、来源是 B 组"的编号错位。

### 2.4 LLM 主备与空响应（`services/llm/openai_adapter.py`）

- 主备互换：`LLM_MODEL=glm-4-flash-250414`，`LLM_FALLBACK_MODELS=glm-4.7-flash`。
  实测 glm-4.7-flash 三测两 429，唯一成功一次耗时 25.6s 且返回**空 content**；glm-4-flash-250414 稳定 2-3s。
- 新增空内容保护：HTTP 200 但 content 为空视为失败（先同模型重试，再换备用模型），流式侧"零 token"同样换模型。
- 提示词补两条规则：条件类问题必须分档完整作答；条款需组合时允许一步推导，但不得引入资料外制度。

### 2.5 运维脚本

- `scripts/revectorize.py`：按当前分块策略重灌存量文档（支持 `--kb-id`、`--dry-run`）。
- `scripts/quick_eval.py`：固定 10 题走 HTTP 接口，输出 Hit@3 / 平均上下文 / 多来源占比，可存 JSON 便于前后对比。

## 3. 前后对比（同一 10 题）

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 分块总数 / 中位块长 | 144 / 122 字 | 28 / 约 700 字 |
| Hit@3 | 10/10 | 10/10 |
| 平均上下文长度 | 707 字 | 2276 字 |
| 多来源占比（≥2 份文档） | 7/10 | 10/10 |
| 平均响应时间 | 13.0s | 2.3s（主模型切换后） |
| 降级/空答案 | 偶发 | 0/10 |

结果文件：`backend/evals/results/2026-11-18-quick-*.json`。

## 4. 可配置项

| 配置 | 默认 | 作用 |
|------|------|------|
| `CTX_BUDGET_CHARS` | 2600 | 三条来源合计字符预算。过小会丢跨文档条款（多跳问题直接拒答），过大拖慢生成 |
| `RELEVANCE_THRESHOLD` | 0.02 | RRF 分阈值（与 mock 实测值匹配） |
| `RELEVANCE_COS_THRESHOLD` | 0.5 | 余弦判据兜底（bge-m3 真相关 0.64+，无关 <0.45） |
| `LLM_FALLBACK_MODELS` | `glm-4.7-flash` | 主模型限流/空响应时依次降级 |

## 5. 已知不足（后续可做）

1. 引用编号偶有错位（模型把要点标到相邻编号），需要"引用-原文"一致性校验或重排序后重新编号；
2. 未做重排序（rerank），top-3 顺序仍由 RRF 决定；
3. 评测仍是 10 题小集，缺消融实验（关掉邻块扩展 / 关掉去重各跑一组）。
